<h1 align="center">booster-um</h1>
<p align="center">
  <b>Booster UKI Manager</b><br>
  A simple bash script to manage UKI (Unified Kernel Image) files generated by 
  <a href="https://github.com/anatol/booster">booster</a> and 
  <a href="https://www.freedesktop.org/software/systemd/man/latest/ukify.html">systemd-ukify</a>.<br>
  The script can only be used on <a href="https://wiki.archlinux.org/title/Arch-based_distributions#Active">Arch Linux distributions.</a>.
</p>

<h2 name="dependencies">
    Dependencies
</h2>

 * Required:
   * booster - Generate initramfs
   * go-yq - Parse booster and booster-um configs
   * systemd-ukify - Generate UKI files
   * util-linux - Miscellaneous system utilities for Linux
 * Optional:

   * sbsigntools - Sign UKI files with sbsign
   * efibootmgr - Manage EFI entries

<h2 name="installation">
    Installation
</h2>

If you are using an Arch-based distribution, install [booster-um](https://aur.archlinux.org/packages/booster-um) or [booster-um-git](https://aur.archlinux.org/packages/booster-um-git) package from the AUR. After that you are free to remove `mkinitcpio`.

<h2 name="default_behavior">
    Default Behavior
</h2>

While `/etc/booster-um.yaml` is empty by default, `booster-um` operates with robust out-of-the-box behaviors to handle UKI generation, signing, and partition detection safely.

---

### Core Behavior

By default, `booster-um`:
- **Signs generated UKI files** automatically using `sbctl` **if it is installed** on the system.
- **Uses a default boot splash image** located at `/usr/share/systemd/bootctl/splash-arch.bmp`.
- **Detects the `XBOOTLDR` partition** **if it exists and is mounted on** `/boot`.
- **Falls back to default configurations** if the `/etc/booster-um.yaml` configuration file **is invalid or missing**.
- **Generates UKI binaries** in the `esp/EFI/Linux` directory (automatically creating the directory if it does not exist).
- **Removes old leftovers** (`vmlinuz-*` and `booster-*`) from the `/boot` directory, while **preserving the microcode image**.
- **Always generates fallback images** if the `universal` flag is enabled in the main `/etc/booster.yaml` configuration, regardless of any other initramfs settings.
- **Does not generate default EFI entries or fallback UKI files** out of the box unless explicitly configured.
- **Does not regenerate initramfs files** on kernel and extramodule installations/upgrades, as they are already handled by the upstream **booster hook**.
- **Cleans up known EFI entries** (e.g., `\EFI\LINUX\ARCH-LINUX.EFI`) on kernel removal **if `efibootmgr` is installed** (you can prevent this behavior by enabling `efistub` in your configuration).

---

### Libalpm Hooks Behavior

During package manager operations, the `booster-um` libalpm hooks automatically manage:
- **Kernel Removal**: Removes associated EFI entries and cleans up UKI files from both the ESP and the `sbctl` database.
- **Package Updates**: Regenerates UKI files for all installed kernels whenever **booster**, **microcode**, **dkms**, or **firmware** packages are installed, updated, or removed.
- **UKIs on Upgrades**: Always signs UKI files during kernel upgrades.
- **Exclusions on Updates**: Skips signing newly generated UKI files during **microcode**, **extramodules** (`nvidia`, `nvidia-lts`, etc.), and standard kernel updates (the **sbctl hook** handles these).
- **Automatic Database Sync**: Always signs **newly created** UKI files **if they do not already exist** in the `sbctl` database, meaning you don't need to manually sign or add UKI files to `sbctl`.

<h2 name="config_file">
    Config File
</h2>

For information about configuration, read [this documentation](https://github.com/Zile995/booster-um/blob/main/config/CONFIG.md).

When specific parameters are omitted or left undefined in the `/etc/booster-um.yaml` configuration file, `booster-um` automatically applies the following default values and resolution orders:

| Parameter | Node / Context | Default / Unspecified Value / Fallback Behavior | Explanation |
| :--- | :--- | :--- | :--- |
| `sign_uki` | First level | `true` | Manages UKI signing. |
| `sbsign` | First level | `false` | Delegates UKI signing to `ukify`. |
| `colors` | First level | `true` | Colors terminal output. |
| `efistub` | First level | `false` | Manages EFI entries. |
| `microcode` | First level | `true` | Includes microcode images. |
| `verbose` | First level | `false` | Enables verbose output for booster. |
| `low_memory` | First level | `false` | Sequential initramfs generation to save memory. |
| `enable_splash` | First level | `true` | Enables the boot splash screen. |
| `remove_leftovers` | First level | `true` | Removes old leftovers/files after generation. |
| `generate_fallback` | First level | `false` | Manages creation of fallback UKI files. |
| `append_machine_id` | First level | `false` | Appends system machine ID to filename. |
| `os_id` | First level | Value of `ID` from `/etc/os-release` (e.g., `arch`) | Custom OS identifier prefix for UKI filenames. |
| `cmdline` | First level | If **unspecified**: `/etc/kernel/cmdline` &rarr; Current command line `/proc/cmdline` | Default kernel command line used by all kernels. |
| `fallback_cmdline` | First level | If **unspecified**: Global `cmdline` &rarr; `/etc/kernel/cmdline-fallback` &rarr; `/etc/kernel/cmdline` &rarr; Current command line `/proc/cmdline` | Kernel command line used specifically for fallback images. |
| `cmdline_per_kernel` | `kernel_config` | `false` | Enables setting a custom cmdline for each kernel. |
| `share_default_cmdline` | `kernel_config` | `false` | Shares default command line with kernel packages. |
| `default_initramfs` | `kernel_config` | `[default, fallback]` | Initramfs types configuration for all unspecified kernels. |
| `default_splash` | `kernel_config` | `/usr/share/systemd/bootctl/splash-arch.bmp` | Default splash picture for all kernels. |
| `splash` | `$pkgbase` | Inherits `default_splash` value | Splash picture configuration for an individual kernel. |
| `cmdline` | `$pkgbase` | If **unspecified**: Global `cmdline` &rarr; `/etc/kernel/$pkgbase-cmdline` &rarr; `/etc/kernel/cmdline` &rarr; Current command line `/proc/cmdline` | Command line configuration for an individual kernel. |
| `fallback_cmdline` | `$pkgbase` | If **unspecified**: `$pkgbase cmdline` &rarr; Global `fallback_cmdline` &rarr; Global `cmdline` &rarr; Per-kernel files (`/etc/kernel/$pkgbase-cmdline-fallback` &rarr; `/etc/kernel/$pkgbase-cmdline` &rarr; `/etc/kernel/cmdline-fallback` &rarr; `/etc/kernel/cmdline`) &rarr; Current command line `/proc/cmdline` | Fallback command line configuration for an individual kernel. |
| `initramfs` | `$pkgbase` | Inherits `default_initramfs` value | Initramfs type configuration for an individual kernel. |
| `os_name` | `efistub_config` | Value of `NAME` from `/etc/os-release` (e.g., `Arch Linux`) | Custom OS display name prefix for EFI boot entry labels. |
| `append_entries` | `efistub_config` | `true` | Adds newly created EFI entries to the end of the boot order. |

> **Note:** `$pkgbase` = kernel package name

<h2 name="ukify_integration">
    Ukify Integration
</h2>

`booster-um` uses systemd's `ukify` under the hood to assemble UKI binaries. `ukify` automatically reads its default configuration file from `/etc/systemd/ukify.conf` if it exists.

* **CLI Overrides**: Options managed directly by `booster-um` (such as `--linux`, `--initrd`, `--cmdline`, `--splash`, `--uname`, and `--output`) will override matching parameters in `ukify.conf`.
* **Global Options**: Any additional settings configured in `/etc/systemd/ukify.conf` (such as custom UKI sections, or PCR signing policies) will be respected during the build process.

<h2 name="secureboot_configuration">
    Secure Boot Configuration
</h2>

`booster-um` supports two main workflow methods for signing UKI binaries: **`sbctl`** (default) and **`ukify`'s built-in signing tools** (`sbsign` or `systemd-sbsign`).

---

### 1. Using `sbctl` (Default)

By default, if `sbctl` is installed on your system, `booster-um` automatically uses it to sign generated UKI files and keep track of them in the `sbctl` database.

* **Prerequisites**: Install `sbctl` and generate/enroll your keys (`sbctl create-keys`, `sbctl enroll-keys`).
* **`/etc/booster-um.yaml` settings**:

  ```yaml
  sign_uki: true   # Enables signing (default: true)
  sbsign: false    # Keeps sbctl as the active signing tool
  ```

> **Note**: `booster-um` hooks automatically clean up old UKI records from the `sbctl` database when kernels are removed.

---

### 2. Delegating Signing to `ukify` (`sbsign` / `systemd-sbsign`)

If you manage Secure Boot keys manually or prefer delegating the signing process directly to `ukify`, set `sbsign: true` in your configuration.

* **`/etc/booster-um.yaml` settings**:

  ```yaml
  sign_uki: true   # Must remain enabled. (default: true)
  sbsign: true     # Disables sbctl and delegates signing entirely to ukify
  ```
> **Important**: When `sbsign: true` is enabled, `booster-um` automatically removes generated UKI files from the `sbctl` database if they were previously tracked. This prevents the `sbctl` pacman hook from re-signing these images during system updates.

#### Configuring Signing in `/etc/systemd/ukify.conf`

When `sbsign: true` is enabled, key paths and signing preferences are configured entirely inside `/etc/systemd/ukify.conf`. You can choose between two signing tools:

* **Using `sbsign`** (Requires `sbsigntools` package):
  ```ini
  [UKI]
  SecureBootPrivateKey=/etc/secureboot/keys/db/db.key
  SecureBootCertificate=/etc/secureboot/keys/db/db.crt
  ```

* **Using `systemd-sbsign`** (No extra packages required):
  If `sbsigntools` is not installed, you can specify `systemd-sbsign` as the signing tool:
  ```ini
  [UKI]
  SignKernel=true
  SecureBootSigningTool=systemd-sbsign
  SecureBootPrivateKey=/etc/secureboot/keys/db/db.key
  SecureBootCertificate=/etc/secureboot/keys/db/db.crt
  ```
  > **Note**: Do not forget to enable `SignKernel` option, `systemd-sbsign` requires this option to be enabled.
---

### 3. Disabling UKI Signing

To completely skip UKI signing (e.g., if Secure Boot is disabled or handled elsewhere), update `/etc/booster-um.yaml`:

```yaml
sign_uki: false
```
> **Note**: When `sign_uki: false` is set, `booster-um` automatically removes UKI files from the `sbctl` database to prevent the `sbctl` pacman hook from unexpectedly signing them during system updates.

<h2 name="first_run">
    First Run
</h2>

Follow these step-by-step instructions to perform your initial setup and generate UKI files.

---

### 1. Configure Kernel Command Line

Define your kernel parameters in either `/etc/booster-um.yaml` or `/etc/kernel/cmdline`. 

> **Important**: Ensure you remove any existing entries pointing to **microcode**, **vmlinuz**, or **initramfs** images, as these are managed automatically.

- **Example `/etc/booster-um.yaml`**:
  ```yaml
  cmdline: >
    root=UUID=0a3407de-014b-458b-b5c1-848e92a327a3
    rw
    quiet
    splash
  ```
  
- **Example `/etc/kernel/cmdline`**:
  ```ini
  root=UUID=0a3407de-014b-458b-b5c1-848e92a327a3 rw quiet splash
  ```
  
---

### 2. Configure `booster-um` Settings

Edit `/etc/booster-um.yaml` according to your boot requirements. If left empty, sensible defaults will be applied automatically.

- **Fallback Generation**: If you want to enable the generation of fallback UKI images:

  ```yaml
  generate_fallback: true
  ```

- **Splash Image**: If you do not want a splash image during boot, disable it:

  ```yaml
  enable_splash: false
  ```

- **EFISTUB Booting**: If you intend to boot directly via UEFI without a bootloader, enable EFISTUB:
  ```yaml
  efistub: true
  efistub_config:
    default_entry: "linux"  # Set default kernel package to boot into
  ```

- **Secure Boot Setup**:
  - **Using `sbctl`**: Ensure keys are generated before building UKIs (`sbctl create-keys && sbctl enroll-keys`).
  - **Using `sbsign`**: Set `sbsign: true` in the config if using custom keys.
  - **No Signing**: Set `sign_uki: false` if you don't want images to be signed.
  - *For complete configuration options and workflows, see the [Secure Boot configuration](#secureboot_configuration) section.*
  
> **Reference**: For detailed guide on key creation, consult the [Arch Wiki: UEFI/Secure Boot](https://wiki.archlinux.org/title/Unified_Extensible_Firmware_Interface/Secure_Boot) article.

---

### 3. Configure Global Booster Settings (Optional)

Besides `booster-um`, you can configure the main **booster** generator itself by editing `/etc/booster.yaml`. This file controls general image generation options such as compression algorithms, embedded modules, microcode, and binary stripping.

- **Example `/etc/booster.yaml`**:
  ```yaml
  # Compression algorithm for the initramfs image (e.g., zstd, xz, gzip, none)
  compression: zstd

  # Mount timeout for root filesystem
  mount_timeout: 10s

  # Modules to force-load during early boot
  modules: -*,btrfs,nvme

  # Strip debug symbols from binaries and modules to reduce image size
  strip: true

> **Note**: If `universal: true` is enabled in `/etc/booster.yaml` (or via per-kernel `booster_config`), **booster-um** will only generate fallback UKI files, regardless of the settings configured in `/etc/booster-um.yaml`.

> **Reference**: For a full list of supported parameters, refer to the official [Booster Config Documentation](https://github.com/anatol/booster/blob/master/docs/manpage.md#config-file).

  ---

### 4. Clean Legacy Initramfs & Leftovers (Optional)

You can clean up all cmdline files, old booster initramfs, vmlinuz kernels and old initramfs files generated by other generators/hooks (e.g., `mkinitcpio`, `dracut`) along with the existing `esp/EFI/Linux` directory using:

```bash
sudo booster-um -C
```

> **Data Loss Warning**: Do **not** run `booster-um -C` if you multi-boot with other Linux distributions. This command completely removes the `esp/EFI/Linux` directory, which may contain UKI binaries from other installed systems.

---

### 5. Generate UKI Files & Boot

1. **Generate images**: Run the following command to build all UKI binaries:

   ```bash
   sudo booster-um -G
   ```
2. **Booting**: If `systemd-boot` is installed, it will automatically detect and list the newly generated UKI files in `esp/EFI/Linux`.

> **Note**: After making any changes to the configuration files, you should run `sudo booster-um -G` to regenerate the UKI files and apply the configuration updates.

> **Reference**: For more details on supported bootloaders, see the [Arch Wiki: Unified Kernel Image](https://wiki.archlinux.org/title/Unified_kernel_image#Booting) guide.

<h2 name="configuration_examples">
    Configuration Examples
</h2>

While `/etc/booster-um.yaml` is empty by default, you can customize your boot behavior, command lines, and kernel-specific rules. 

### Example 1: Basic Custom Configuration

This setup demonstrates generating fallback UKI images, setting global/fallback command lines, and applying kernel-specific overrides:

```yaml
generate_fallback: true

cmdline: >
  root=LABEL=arch_root
  rw
  quiet
  loglevel=3
  udev.log_level=3

fallback_cmdline: >
  root=LABEL=arch_root
  rw
  sysrq_always_enabled=1

kernel_config:
  default_initramfs: [default]
  linux-lts:
    splash: false
    initramfs: [fallback]
```

#### What this configuration does:
- **`generate_fallback: true`**: Enables the creation of fallback UKI images.
- **Global `cmdline` & `fallback_cmdline`**: Defines robust default kernel parameters applied to all default and fallback boots.
- **`kernel_config`**: 
  - Sets `default_initramfs: [default]` to build only default initramfs images for all unspecified kernels by default.
  - Targets `linux-lts` to explicitly disable the boot splash (`splash: false`) and force it to build only a `fallback` initramfs type (`initramfs: [fallback]`).

---

### Example 2: Advanced Configuration with EFISTUB & `systemd-sbsign`

This setup demonstrates delegating Secure Boot signing and TPM2 PCR signatures to `ukify` using `systemd-sbsign`, combined with EFISTUB entry management (assuming the `linux` kernel is installed).

#### 1. `/etc/systemd/ukify.conf`
```ini
[UKI]
SignKernel=true
SecureBootSigningTool=systemd-sbsign
SecureBootPrivateKey=/etc/secureboot/keys/db/db.key
SecureBootCertificate=/etc/secureboot/keys/db/db.crt

[PCRSignature:initrd]
Phases=enter-initrd
PCRPrivateKey=/etc/systemd/tpm2-pcr-initrd-private-key.pem
PCRPublicKey=/etc/systemd/tpm2-pcr-initrd-public-key.pem

[PCRSignature:system]
Phases=enter-initrd:leave-initrd enter-initrd:leave-initrd:sysinit
       enter-initrd:leave-initrd:sysinit:ready
PCRPrivateKey=/etc/systemd/tpm2-pcr-private-key-system.pem
PCRPublicKey=/etc/systemd/tpm2-pcr-public-key-system.pem
```

#### 2. `/etc/booster-um.yaml`
```yaml
sbsign: true
generate_fallback: true

cmdline: >
  root=LABEL=arch_root
  rw
  quiet
  loglevel=3
  udev.log_level=3
  sysrq_always_enabled=1

kernel_config:
  default_initramfs: [default]
  linux-lts:
    splash: false
    initramfs: [fallback]

efistub: true
efistub_config:
  default_entry: linux
```

#### What this configuration does:
- **`sbsign: true`**: Instructs `booster-um` to delegate binary signing directly to `ukify`, which uses `systemd-sbsign` and signs PCR policies for TPM2 auto-unlocking defined in `/etc/systemd/ukify.conf`.
- **`efistub: true`**: Enables direct UEFI booting without needing a bootloader, setting `linux` as the primary default boot entry (`default_entry: linux`).
- **Command Line Inheritance for `linux-lts`**: Because a custom cmdline is not defined under the `linux-lts` block, it automatically inherits the global `cmdline `defined at the top level of this configuration.

---

### Example 3: Dual-Boot Setup (Two Arch Linux Installations)

When dual-booting two installations of the same Linux distribution on a shared EFI System Partition (ESP), file name collisions and duplicate boot labels can occur. This setup demonstrates customizing `os_id`, `os_name`, and appending machine IDs to distinguish each system cleanly.

> Note: If you are using a secondary bootloader like **systemd-boot**, it automatically discovers UKI files from `esp/EFI/Linux` dir. In such cases, it is sufficient to change `os_id`, or enable `append_machine_id` to prevent file conflicts.

```yaml
os_id: "arch-work"

cmdline: >
  root=UUID=12345678-1234-1234-1234-123456789abc
  rw
  quiet

efistub: true
efistub_config:
  os_name: "Arch Linux Workstation"
  default_entry: linux
```

#### What this configuration does:
- **`os_id: "arch-work"`**: Overrides the default `os_id` (`arch`) to use a unique filename prefix, preventing UKI binaries on the shared ESP from overwriting each other (e.g., `/EFI/Linux/arch-work-linux.efi`).
- **`efistub_config.os_name: "Arch Linux Workstation"`**: Sets a custom display label in the UEFI boot menu (e.g., **Arch Linux Workstation (linux)**), making it easy to distinguish between installations in the boot manager.

---

### Example 4: Per-Kernel Booster Configuration

You can pass custom parameters directly to `booster` for a specific kernel (such as changing compression options or bundling extra files/binaries) using `booster_config` inside `kernel_config` node:

```yaml
cmdline: >
  root=UUID=12345678-1234-1234-1234-123456789abc
  rw
  quiet

kernel_config:
  linux:
    booster_config: |
      compression: lz4
      extra_files: busybox,fsck,fsck.ext4
```

#### What this configuration does:
- **`kernel_config.linux.booster_config`**: Injects a custom multi-line booster configuration specifically for the `linux` kernel build.
- **`compression: lz4`**: Overrides the default initramfs compression method to use `lz4` for `linux`.
- **`extra_files`**: Explicitly includes required binaries and utilities (`busybox`, `fsck`, `fsck.ext4`) directly inside the generated initramfs for that kernel package.

___

### Example 5: Per-Kernel Command Line Configuration

This setup demonstrates how to enable individual command-line options per kernel while sharing common boot parameters across all kernels using `share_default_cmdline`.

```yaml
generate_fallback: true

cmdline: "root=UUID=12345678-1234-1234-1234-123456789abc rw"

kernel_config:
  cmdline_per_kernel: true
  share_default_cmdline: true
  default_initramfs: [default]
  linux:
    cmdline: >
      quiet
      loglevel=3 udev.log_level=3
      zswap.enabled=0
  linux-lts:
    splash: false
    cmdline: "sysrq_always_enabled=1"
    initramfs: [fallback]
```

#### What this configuration does:
- **`cmdline_per_kernel: true`**: Enables defining separate `cmdline` parameters for individual kernels under their respective `pkgbase` nodes inside `kernel_config`.
- **`share_default_cmdline: true`**: Appends the specific kernel's `cmdline` to the global `cmdline` (`root=UUID=12345678-1234-1234-1234-123456789abc rw`), preventing the need to repeat basic parameters across multiple kernel definitions.
- **`linux`**: Combines the global `cmdline` with **kernel-specific** `cmdline` (`quiet loglevel=3 udev.log_level=3 zswap.enabled=0`).
- **`linux-lts`**: Appends `sysrq_always_enabled=1` to the **global** `cmdline`, disables the boot splash (`splash: false`), and builds only the `fallback` initramfs image (`initramfs: [fallback]`).

#### Resulting Command Lines in this Example:
 - `linux` **(default initramfs)**:
    `root=LABEL=arch_root ro quiet loglevel=3 udev.log_level=3 zswap.enabled=0`
 - `linux-lts` **(fallback initramfs)**:
    `root=LABEL=arch_root ro sysrq_always_enabled=1`

> **Note on Command Line Resolution in this Example**: 
> For `linux-lts` (which builds a `fallback` initramfs), `booster-um` first checks for a kernel-specific `fallback_cmdline`. Since `fallback_cmdline` is not defined under `linux-lts` in this example, it directly uses its kernel-specific `cmdline` (`sysrq_always_enabled=1`). Had this not been defined either, it would have fallen back to checking the global configuration—first for a global `fallback_cmdline`, and if absent, the global `cmdline`.

<h2 name="usage">
    Usage
</h2>

```Shell
Usage: booster-um [OPTIONS] <package>

Manage UKI files generated by booster and systemd-ukify.

Options:
    -h, --help    Show this help message
    -v, --version Print version

Generate options:
    -g <package>  Generate UKI file for specified kernel package name
    -G            Generate UKI files for all installed kernels

Remove options:
    -o            Remove orphaned EFI entries
    -r <package>  Remove UKI file for specified kernel package name
    -C            Remove initramfs*, booster*, vmlinuz* files, entire esp/EFI/Linux dir and other leftovers
    -R            Remove known booster*, vmlinuz*, UKI files and other leftovers for all installed kernels

Examples: booster-um -g linux
          booster-um -g linux linux-lts
          booster-um -r linux-zen linux-lts
          booster-um -G
          booster-um -R
          booster-um -C
```
